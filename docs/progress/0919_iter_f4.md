## 偏离与决定（重要）

1. **scroll 族的 parallax/scrub/scrub-draw 没有采用 CSS `view()` 时间线**（规格原文：CSS scroll-driven 优先）。实测（Chromium 145 headless，含最小复现页）：`view()` 的滚动容器解析按规范把 `overflow:hidden` 的 `.slide` 画布当作最近滚动容器（overflow:hidden 也是滚动容器），进度冻结在初值——骨架画布必须 overflow:hidden，两者根本冲突。决定：这三个 recipe 改由**骨架 JS 滚动驱动**——rAF 节流监听 deck scroll，把页穿越视口进度写为 `.slide` 上的 `--sp ∈ [0,1]`，CSS 用 calc 消费（强度上限仍烧死在 CSS 公式里，不写 DOM 结构）。`read-progress`（整 deck 进度语义）保留纯 CSS scroll-timeline 并实测通过。--sp 缺省值 = 静态终态，无 JS/reduced-motion/编辑器冻结下内容完整可见。motion.md §7 与契约 v6 已同步此口径。
2. **read-progress 必须是 `.deck` 的最后一个子元素**（不能放 body 级）：具名 scroll-timeline（--deck-scroll）只对时间线声明元素的后代可见。已写入骨架注释与 motion.md。
3. **ring 的 `transform: rotate(-90)` 不能写在 circle 属性上**：CSS `transform:none`（data-anim 通用规则）会覆盖 SVG transform 属性（呈现属性优先级最低）——验收 deck 把旋转放在外层 `<svg style="transform:rotate(-90deg)">`（方形 viewBox 旋转对称安全）。此约束已隐含在 motion.md ring 实现要点（pathLength + --val）中，生成侧注意勿给 data-anim 的 SVG 元素写 transform 属性。
4. 词汇表实收 **39 个 recipe**（规格 "~32"）——规格自身枚举的两轮清单合计即超 32，未再削减；反目录覆盖纪律（每 deck ≤4 族）约束使用量而非词汇量。
5. 面板 motion 组旧选项（无/克制/强）替换为五层矩阵三档（克制/标准/华丽），默认从 `subtle` 改为 `standard`；旧档 id 不再兼容（面板是意图收集、无持久化，无兼容负担）。
6. 验收 deck 有意在同页并列多个主动效（夹具注释已声明），生产 deck 的"每页主动效 ≤1"纪律不变。
