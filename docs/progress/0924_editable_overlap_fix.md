# 0924 · 可编辑轨文字重叠：归因与五层加固方案

> 2026-09-24 · 触发：cmb-retail 54 页真实基准 deck 导出后，用户在效果图中看到**大量文字重叠**。
> 本文档 = 问题归因 + 解决方案（经七维自审）。实施记录待完成后追加。

## 一、归因（四个叠加漏气点）

可编辑轨把 Chromium 排版结果"转述"给 PowerPoint，重叠来自四处：

1. **行距口径不一致（行内重叠主因）**：`line-height×0.5pt` 写成 spcPts 精确行距，但 CJK 字体自然行高（ascent+descent+lineGap）普遍 ≥1.4× 字号；PowerPoint 遇到"精确行距 < 字体自然行高"时行与行直接叠字（浏览器有兜底，pptx 没有）。
2. **框高零冗余（跨块重叠放大器）**：框高=渲染高度的紧配合，任何行距/字体差异直接溢出压下方元素。slide-paipai README 坑位记录实证过同款失败（逐行 a:p 累积误差下溢），其解法=框高白送一行余量。
3. **字体未随档（度量前提失效）**：cmb-retail 无 fonts/ 子集，目标机缺苹方/宋体时全部字宽字高漂移，按 Chromium 实测的框宽框高作废。C3 建的 fntdata 内嵌能力未默认启用。
4. **可编辑轨无出厂回验（双轨不对称）**：保真轨有像素 diff 门禁，可编辑轨只有几何抽验——重叠是出厂后被用户眼睛发现的。
5. 次要：首行基线未按字体 ascent 校准（系统性纵向偏移；slide-paipai 用 y−5px 补偿同款问题）。

调研依据：tencent-pptx（单引擎 DSL 从架构上无双引擎差；lint 门禁"不过不落盘"纪律可借）、slide-paipai（PIL 实测+整段自折+一行余量+last_y 构造性防重叠）、ppt-master（字体表/内嵌机制）。

## 二、方案：五层叠加（目标：重叠/超标页 <1%）

思路转变：**不追求"永不重叠"，追求"重叠页出不了厂"**。

1. **字体随档默认化【根治】**：可编辑轨导出时自动跑防线 A——fc-list 解析主题字体栈到本机 TTF → subset-fonts（ttf）→ fntdata 内嵌（fsType 闸）；找不到字体文件才回退映射+报告。
2. **行高与基线校准【根治行内重叠】**：lnSpc = max(作者行高, 字体自然行高×1.03)（自然行高从内嵌字体经 fontTools 实测）；文本框 top 按 ascent 差值补偿，首行基线与 HTML 对齐。
3. **松配合【吸收残余误差】**：框高 = 渲染高 +1 行、框宽 +2%、顶对齐、单行标题禁折行（slide-paipai 实测口径）。
4. **导出时几何自净【静态拦截】**：同页原生元素包围盒两两相交扫描，超限先收余量、仍冲突则该块烙图降级；带伤不出厂。
5. **LO 渲染回验 + 逐页混合降级【出厂门禁】**：LibreOffice 渲染 deck.pptx 逐页与 HTML 截图 diff（复用保真轨设施）；超标页自动换保真轨 svgBlip 载体——单页粒度汇合双轨。门禁阈值：cmb-retail 54 页压测，超标页 <1%（=0 页）。

1–2 消根因，3–4 兜残差，5 是 <1% 的闭环保证。

## 三、自审风险表

| 维度 | 风险 | 说明 |
|---|---|---|
| 外溢 | 低 | 改动集中在 export-pptx-editable.py + p_editable_check；保真轨/契约/编辑器零改动 |
| 性能 | 低 | LO 回验 +1–2 min/54 页（可 --skip-verify）；相交扫描可忽略 |
| 维护 | 低 | 回验复用保真轨 diff 设施 |
| 根因 | 高 | 1/2 消根因，3/4/5 有界兜底链 |
| 兼容 | 中 | 门禁收紧后个别页降级矢量页——刻意质量收紧，报告逐页声明 |
| 边界 | 已列 | 字体缺失→回退+余量模式；LO 不可用→跳过回验并声明；fsType 受限→余量模式 |

## 四、用户已拍板的取舍

- ⑤ 超标页自动降级为矢量页：**已确认接受**（2026-09-24 "按你的 progress 文档进行优化"）——代价是个别页不可编辑，收益是 <1% 出厂保证；
- LO 回验是本环境裁判的近似，真实 PowerPoint 渲染仍以人工目检为准（P1-10 遗留项不变）。
