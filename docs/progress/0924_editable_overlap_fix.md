# 0924 · 可编辑轨文字重叠：归因与五层加固方案

> 2026-09-24 · 触发：cmb-retail 54 页真实基准 deck 导出后，用户在效果图中看到**大量文字重叠**。
> 本文档 = 问题归因 + 解决方案（经七维自审）。实施记录待完成后追加。

## 一、归因（四个叠加漏气点）

可编辑轨把 Chromium 排版结果"转述"给 PowerPoint，重叠来自四处：

1. **行距口径不一致（行内重叠主因）**：`line-height×0.5pt` 写成 spcPts 精确行距，但 CJK 字体自然行高（ascent+descent+lineGap）普遍 ≥1.4× 字号；PowerPoint 遇到"精确行距 < 字体自然行高"时行与行直接叠字（浏览器有兜底，pptx 没有）。
2. **框高零冗余（跨块重叠放大器）**：框高=渲染高度的紧配合，任何行距/字体差异直接溢出压下方元素。slide-paipai README 坑位记录实证过同款失败（逐行 a:p 累积误差下溢），其解法=框高白送一行余量。
3. **字体未随档（度量前提失效）**：cmb-retail 无 fonts/ 子集，目标机缺苹方/宋体时全部字宽字高漂移，按 Chromium 实测的框宽框高作废。C3 建的 fntdata 内嵌能力未默认启用。
4. **可编辑轨无出厂回验（双轨不对称）**：保真轨有像素 diff 门禁，可编辑轨只有几何抽验——重叠是出厂后被用户眼睛发现的。
5. 次要：首行基线未按字体 ascent 校准（系统性纵向偏移；slide-paipai 用 y−5px 补偿同款问题）。

调研依据：tencent-pptx（单引擎 DSL 从架构上无双引擎差；lint 门禁"不过不落盘"纪律可借）、slide-paipai（PIL 实测+整段自折+一行余量+last_y 构造性防重叠）、ppt-master（字体表/内嵌机制）。

## 二、方案：五层叠加（目标：重叠/超标页 <1%）

思路转变：**不追求"永不重叠"，追求"重叠页出不了厂"**。

1. **字体随档默认化【根治】**：可编辑轨导出时自动跑防线 A——fc-list 解析主题字体栈到本机 TTF → subset-fonts（ttf）→ fntdata 内嵌（fsType 闸）；找不到字体文件才回退映射+报告。
2. **行高与基线校准【根治行内重叠】**：lnSpc = max(作者行高, 字体自然行高×1.03)（自然行高从内嵌字体经 fontTools 实测）；文本框 top 按 ascent 差值补偿，首行基线与 HTML 对齐。
3. **松配合【吸收残余误差】**：框高 = 渲染高 +1 行、框宽 +2%、顶对齐、单行标题禁折行（slide-paipai 实测口径）。
4. **导出时几何自净【静态拦截】**：同页原生元素包围盒两两相交扫描，超限先收余量、仍冲突则该块烙图降级；带伤不出厂。
5. **LO 渲染回验 + 逐页混合降级【出厂门禁】**：LibreOffice 渲染 deck.pptx 逐页与 HTML 截图 diff（复用保真轨设施）；超标页自动换保真轨 svgBlip 载体——单页粒度汇合双轨。门禁阈值：cmb-retail 54 页压测，超标页 <1%（=0 页）。

1–2 消根因，3–4 兜残差，5 是 <1% 的闭环保证。

## 五、实施记录（2026-09-24 完成）

五层全部落地于 `export-pptx-editable.py`（保真轨零行为变更；契约/skeleton 未动）：

- **L1 字体随档默认化**：fc-match 把三栈族名解析到本机渲染真实字体（fontconfig 即
  Chromium 的解析器，替换结果即渲染真相）→ subset-fonts 逻辑子集化 TTF → fntdata 内嵌。
  cmb-retail 实测：Helvetica Neue/PingFang SC/SF Mono 三栈全部落到 Noto Sans CJK JP
  （fsType=0x0000 过闸），2 个 TTF 入档（latin 栈与 mono 栈合并同一族）；族名回写 run
  的 latin/ea（CJK 字体双回写 latin——浏览器拉丁字形也来自它）。踩坑：TTC 集合取 0 号；
  族名 ID16 优先、ID1 剥 " Regular" 样式后缀（否则 embeddedFont 与 run 不匹配）；
  度量/CJK 判定必须读全量字体（子集 cmap 只剩 deck 用字会误判）。
- **L2 行高/基线校准**：Noto CJK 自然行高系数实测 1.480；lnSpc=max(作者值, ×1.03×自然）。
  校准前后对比样例：smartforge 'impact' 页 LO diff 9.10%（校准前同页 7.7% 为字体替换
  基线噪声；校准的扩散是 PPT 正确渲染的签名，见 L5 阈值修订）。
- **L3 松配合**：+1 行/×1.02/单行 wrap=none。实测余量与密集排版大面积碰撞 → 由 L4 收回
  （cmb-retail 收余量 1633 处），证明"先松后收"顺序正确。
- **L4 几何自净**：cmb-retail 消解 1639 处（收余量 ~1600 + 烙图 28 元素 + 图表容器若干，rasterize-chart 为校验失败容器）。
  关键迭代：位图豁免——烙图产物若继续参与扫描会二次冲突成死循环（raster×text 残留
  8 页事故），豁免后零残留。
- **L5 回验**：发现 5% 像素阈值证伪（见设计 §8 证据修订）→ 改为文本字符多重集覆盖率

- **连带修复**：快照强制 content-visibility:visible 全量排版（远屏页逐字 rect 塌缩
  成假单行——'师；' 孤儿行事故）；页背景渐变烙整页底（cover 96% 灾难差根因）；
  tt-outline/gradient-flow 透明填充文字还原本色。

## 六、二次诊断与方案修订（2026-09-28）

**触发**：加固后用户在真实 PowerPoint/WPS 仍见 p6/p10/p13/p26/p27/p29/p34 容器重叠与标题异常换行。XML 级二次诊断（/tmp/diag/REPORT.md）根因排序：

- **R3（元 bug，最大）**：L4 相交扫描把 L3 的宽余量当冲突收回——1749 框中 93% 失去余量；p10 标题框宽与文字实测宽逐点相等（450.0pt=450.0pt），任何度量 epsilon 即重排；
- **R2（重叠主力）**：L2 行距校准放大 100% 段落（lnSpc/字号 >1.40 全量命中），多行块逐行累积下溢压下方容器（p27 块需求 55.8pt vs 框 41.8pt）；
- **R1**：WPS 不支持 fntdata 内嵌（平台事实）+ 单行框零宽余量（全角引号回退宽度差可达 24%）；
- **R4**：门禁双盲——fontconfig 把内嵌族名解析回本机字体（剥不剥内嵌渲染逐点相同），像素 diff 对重叠钝感。

**用户修订意见（2026-09-28）【方案级转向】**：文本框重叠/边距过小**不应依赖视觉 QA**——视觉验收在此场景不可信赖；应**写入 pptx 后直接读结构化文件做数学计算认证**，只有严谨数学才能保证 100% 不发生。

### 修订后方案（F1–F4′）

- **F1 墨水盒判定（修 R3）**：相交判定对象从"框"改为"墨水盒"（行数×实际行距+内边距）；余量区允许伸入空白，墨水相碰才算冲突；
- **F2 行距模型重做（修 R2）**：单行/标题 wrap=none 永不重排 + 框宽按回退字体实测 ×1.08（标点密集 ×1.15）；多行块 lnSpc 以自然行高为下限、块高=Σ实际行距重新预算，超隙用 normAutofit 缩字 3–5% 而非硬压行距；
- **F3 字体交付分级（修 R1）**：run typeface 写目标机必有字体（雅黑/等线映射，WPS 可预测），内嵌保留为 365 增强；交付话术：WPS 用户走 deck-vector.pptx/deck.pdf；
- **F4′ 数学认证门禁（修 R4，替代视觉回验主裁判地位）**：新脚本 `certify-pptx.py`——重开产物 XML，逐文本框做纯计算认证：
  1. **逐行墨水宽**：run 文本 × 字体文件实测 advance（fontTools 读 hmtx，候选字体集=内嵌字体+雅黑+宋体+苹方，逐行取**最坏值**）+ letter-spacing，vs 框内净宽——水平溢出 = 0 硬要求；
  2. **逐块墨水高**：Σ 段落 lnSpc（与自然行高下限取大）+ 内边距，vs 框高——垂直溢出 = 0 硬要求；
  3. **行内不叠字**：lnSpc ≥ 候选字体集最坏自然行高——逐段可证；
  4. **墨水盒两两相交 = 0**（分层感知：文字-文字严格；文字-背景形状按 z 序豁免）；文字墨水与容器边距 ≥4px；
  5. 认证不过的元素 → 自动修复环（放宽/缩字/烙图）→ 重认证；页级修不净 → 该页降级矢量件。
  认证在声明的候选字体集合内是**数学保证 100%**（换行点固定=逐行段落模型使宽度计算精确，无需模拟 PPT 换行引擎）；集合外字体（极端定制机）由 F3 交付话术兜底。LO/像素回验降级为参考通道。

## 七、治本转向：容量约束前置到 HTML 搭建期（2026-09-29）

**触发**：四轮修复后 cmb-retail 仍有 16 页结构性超容被页级降级（Chromium 混排紧凑度量能装下的卡片，PPT 度量装不下）。用户裁决：**不接受降级——要完全可 native 编辑的 pptx；文字原本就来自真实 pptx，只要布局正确必然放得下；要求从 HTML 搭建时进行程序化约束**。

### 治本方案（单一度量引擎贯穿四环）

核心：**HTML 侧的容量预算必须用 PPT 度量口径，而非浏览器口径**。

1. **统一度量引擎已建成**：`pptx_text_metrics.py`（C4 产物）即完整 PPT 度量模型（混排边界 +1em/对、自然行高、候选字体集最坏值）。
2. **新增 `scripts/check-capacity.py`【生成侧硬门禁】**：对渲染后 DOM 逐容器计算——容器内全部文本叶在 **PPT 度量下的贪心换行**（逐字 advance + 混排边界 + CJK 禁则 + 拉丁词界）所需行数 × 自然行高 + padding，vs 容器净高净宽；单行文本直接比宽度。超限即违规，生成侧必须重排（减字/拆卡/降档字号/加容器）才能交付。嵌入 SKILL.md Step 5 与渲染校验同闸。
3. **认证即验收**：check-capacity 与 certify-pptx 共用同一度量模块——生成侧过了容量闸，导出数学认证必然过，**零降级成为可达目标**。
4. **typography.md 防线 D 量化升级**：容器余量纪律从"≤85% 高"升级为"PPT 度量行数×自然行高 ≤ 容器净高"的可机检硬规则。
5. **cmb-retail 16 页重排**：用容量校验器出超限清单 → 按规则重排（减 padding/拆卡/字号降档/拆页）→ 容量 0 违规 → 重导出目标 degraded_pages=0、全文原生可编辑。

### 与既有防线的关系

- 渲染校验（j_render_check）管"浏览器里不破版"；容量校验（check-capacity）管"PPT 度量装得下"；认证（certify-pptx）管"产物数学正确"——三闸同模型、各司其职；

**两闸口径差异归因（三层）**：
1. **换行基准不同**：check-capacity（层 A）按容器净宽整叶贪心换行；导出/certify 按叶框宽（渲染宽 ×1.02）逐渲染行 est——容器视角系统性低估行数；
2. **度量常数错误**（受控实验证伪）：0928 的混排边界 1.04em/边界是单行反推。**0929 受控实验**（构造已知宽度 pptx 经 LO 出 PDF，pdftotext -bbox 逐词坐标，证据 `tests/harness/results/diag-c5/spacing/`）：真实值 **0.237em/边界**（取 0.25em，与 Word/PPT 文献 1/4em 吻合；单/双 typeface 无差异、14pt/18pt 一致、空格相邻对不计）。MIXED_BOUNDARY_EM 1.0→0.25；
3. **0.97 容量折扣双算 + 逐渲染行 a:p 锁死断行**：0.97 是边界项缺失时代的补偿，边界项校正后模型与 LO 逐字吻合（524.3 vs 523.9pt），折扣变成纯幻行源（压实密度实测 99.4%+）；且逐渲染行 a:p 把 Chromium 的紧凑断行（无混排间距）锁死为段落边界——PPT 里每段独立重断行、短尾行堆叠（'…交易团队32'+'人。'两段变 3 行，而整段贪心只需 2 行）。改为**逻辑段 a:p**（`<br>` 硬换行分段——leafLines 逐字 Range 聚类时记 hard 标记——段内软换行交还 PPT wrap=square 贪心重排），est 行数用统一 `greedy_wrap_lines`（metrics 模块，CJK 逐字/拉丁词界/长词硬断/边界 0.25em），certify/apply_layout/check-capacity 三处同函数。

**两闸同数学的落地**：certify-pptx.py 抽取 `certify_elements`（XML 路径与快照路径同一实现）；export-pptx-editable.py 新增 `slide_elements_from_snap`（与 build_pptx 发射逐项同构：z 序/EMU 取整/字体映射/insets=0/ig 组序）；check-capacity.py 升级为双层——层 A 容量视图（原三规则，生成语言指名容器）+ 层 B 几何预认证（快照→plan_fonts 候选集→apply_layout→slide_elements_from_snap→certify_elements 直跑 R1–R4c）。**同数学实证**：层 B 在 cmb-retail 报 144 项，与 certify 对真实产物的第一轮判定逐元素一致（143/143 唯一三元组，差异仅为形状命名）。
