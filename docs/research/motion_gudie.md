
## 一、三条"底层原理"（决定"能不能动"）

这三条是物理层，违反了就一定会翻车，不管设计多用心。

### 原理 1：动效是"注意力预算"，不是"装饰预算"
人的注意力在一屏内**最多同时追 1 个主动效 + 2~3 个背景动效**。超过就变成"哪儿都在动，等于哪儿都没动"，用户会本能地眯眼、快速下滑。

- **主动效**：叙事驱动、大幅位移或颜色变化、时长 >600ms（Shatter Title、Leak Bar 修复、Ticker 数字滚）
- **背景动效**：呼吸、粒子、扫描线、cursor spotlight——时长长、幅度小、不承载信息
- 一屏内主动效 **必须只有 1 个**。你现在的 Hero 只有 Shatter Title 一个主动效，是对的；Pain 章节主动效是 Leak Bar，其他都是背景，也是对的。

### 原理 2：动效必须承担"信息职能"之一
每个动效落地前，先问一句"它在告诉用户什么"。如果答不上来，就删掉。合法职能只有五种：

| 职能 | 例子 | 你页面里对应的 |
|---|---|---|
| **① 揭示内容存在**（entry）| fade-in / slide-in | `.reveal`、arch-layer 滑入 |
| **② 传达数据/状态变化**（transform）| count-up / progress bar | Ticker `¥2000→¥0`、Leak Bar `94%→0%` |
| **③ 建立空间/因果关系**（causality）| 箭头脉冲、连线绘制 | Pipeline 箭头能量点、扫描线 |
| **④ 指示可交互性**（affordance）| hover 反色、光标跟随 | Pain 卡片反色、Cursor Spotlight |
| **⑤ 维持"活着"的存在感**（ambience）| 呼吸、极慢漂移 | Live 脉冲、Grid drift、Foot 水印 |

**判断动效是否合格 = 是否清晰归属其中一种**。属于两种以上说明它过重（比如带位移的呼吸=①+⑤混淆，不要）。

### 原理 3：动效时长要匹配"信息密度"
时长不是拍脑袋的。有一条经验公式：

> **动效时长 ≈ 300ms + (用户需要理解的信息比特数) × 200ms**

- Fade 出现一个标签（0 bit 新信息）：**300ms**
- Slide-in 一张卡（1 bit：位置）：**500ms**
- Count-up 一个数字（3 bit：起点、终点、方向）：**1200–1800ms**
- Shatter 一个标题（4 bit：字符散布+聚合+颜色+完成态）：**~1800ms**
- 无限循环（呼吸/漂移）：**≥ 3s**，越缓越好，越慢越"高级"

**别让 fade 慢到 1s，也别让 count-up 快到 500ms**。这是最常见的翻车点。

## 二、六条"组合原则"（决定"怎么动才好看"）

原理讲的是"该不该"，原则讲的是"怎么搭"。

### 原则 1：Choreography（编舞）—— 用"stagger"制造节奏
连续多个同类元素**永远不要同时动**。用 `stagger` 制造从左到右、从上到下、从中心到边缘的时序。

- 你的 Shatter Title `i * 48ms + random(100)`——完美
- Ticker 三格 `i * 220ms`——完美
- Marquee 3D tilt `i * 60ms`——完美

**判断公式**：stagger 步长 ≈ `单元素动效时长 / 元素数量 × 1.2`。太密没节奏，太稀显拖沓。

### 原则 2：Reveal → Hold → Interact（三段式）
一屏动效的完整生命周期应该是：

```
[进入 800ms] → [静止 ≥ 1500ms] → [用户交互后再触发]
```

**静止期不可省略**。用户需要至少 1.5 秒来读内容。你现在所有 `.reveal` 一次性触发不重复，就是这个原则；但要小心的是**背景动效不能占用静止期的注意力**——所以粒子密度、呼吸幅度都要压得极低。

### 原则 3：Anchor Motion（锚点原则）—— 关键信息**用动效变体独立强调**
一屏内一定有"主角"（Hero 标题、核心数据、CTA），主角配一个**跟别人不一样的动效**。

- Hero 主角是"SMARTFORGE"——用了 shatter（其他标题都是 split-char）✓
- Pain 章节的主角是"漏洞率"——用了 leak-bar（其他卡片元素都是 fade）✓
- Pipeline 的主角是"管道流动"——用了轮转 active + 箭头脉冲（其他都是静态）✓

**每章至少有一个"独有动效"**，让用户"记得住这一屏"。

### 原则 4：Motion Vocabulary（动效词汇表）—— 一致性优先
一个页面**只用 2~3 种缓动函数**，反复用。

推荐组合：
```css
/* 进入 · 温柔 */ cubic-bezier(.22, 1, .36, 1)
/* 变化 · 果断 */ cubic-bezier(.7, 0, .2, 1)
/* 循环 · 平顺 */ ease-in-out
```

你的页面就是这套。多了会显得"哪儿都想炫技"，少了显得单调。

### 原则 5：Motion Follows Meaning（动效方向要匹配内容语义）

| 内容语义 | 推荐动效方向 |
|---|---|
| 增长/上升 | 向上、向右、放大、亮度增加 |
| 流失/漏洞（你 Pain 章节）| 向下、颜色降饱和、红色警示 |
| 修复/优化 | 反向：红→绿/黄、宽度缩短、扫描光 |
| 连接/流程 | 从左到右的方向性动画（Pipeline 箭头脉冲 ✓）|
| 稳定/可靠（金融） | 缓、慢、几乎不动 |
| 创新/科技 | 可以有 3D、透视、粒子 |

**Pain 卡片的 leak-bar 是"红色饱和 → 酸黄"**——语义上是"漏洞被修复"，方向和内容完全同构，这是最强的组合。

### 原则 6：Perceived Performance（感知性能）
真正的规则：**用户觉得快，比实际快更重要**。

- **skeleton + 微动效** 比空白等待感知快 40%
- **入场动画反而让加载感变短**（因为占用了大脑的注意力）
- 但**首屏必须 200ms 内出现骨架**，超过就要 loading state

你的 Shatter Title 1.8s 之所以不显慢，是因为用户被"字母还没归位"吸引住了，没意识到时间在过。

## 三、"内容 → 动效"的直接对照表（可当查询手册）

我按内容类型给你一张"看到这个内容，应该配什么动效"的对照：

| 你在写什么 | 首选动效 | 备选 | 一定不要 |
|---|---|---|---|
| **Hero 标题**（品牌名/口号）| Shatter / Wipe / Split-char | 打字机（谨慎，容易 tacky）| 简单 fade（浪费首屏） |
| **数字对比**（¥2000→¥0）| Count-up + 缓动 | Odometer 翻牌 | 直接显示（无冲击） |
| **进度/占比**（94% leak）| Progress bar + 渐变色 + 扫描光 | 圆环进度 | 静态百分比 |
| **流程/管道**（Input→Forge→Output）| 沿路径的粒子/圆点流动 + stroke-dasharray 画线 | 阶段轮转高亮 | 单纯的静态箭头 |
| **对照矩阵**（Deep vs Wide）| 左右分别 slide-in | fade + 反色 | 同时出现 |
| **卡片列表**（4 大漏洞）| Stagger fade-up | 3D tilt entry | 同步出现 |
| **图片走廊**（Marquee）| 3D perspective tilt + hover 抬升 | 简单横滚 | 无 hover 反馈 |
| **CTA 按钮** | 呼吸边框 / hover 扫光 | 磁性吸附 | 太多状态（分散点击欲） |
| **数据卡组**（Ticker 3 格）| Stagger count-up | 逐个 flip | 全部同时 |
| **章节切换** | Parallax + 大字水印呼吸 | 横滑 | Hard cut |
| **列表项**（li）| stagger fade-left（跟阅读方向）| 逐个绘制左侧标记 | 全部一起 |

## 四、放在你的 SmartForge 页面上做个"复盘打分"

我给你现在这份页面的动效架构打个分（10 分制）：

| 章节 | 主动效 | 动效职能 | 得分 | 备注 |
|---|---|---|---|---|
| Hero | Shatter Title | 揭示+建立品牌 | 9 | 唯一遗憾是酸黄词的持续 float 太轻，可稍强 |
| Pain | Leak Bar 修复 | 数据变化+叙事 | **10** | "红→酸黄"完美匹配"漏洞→修复"叙事，这是全页最强的动效 |
| Pipeline | 三段轮转 + 箭头脉冲 | 因果关系 | 8 | 轮转周期 2.2s 略快，建议 2.8s；箭头脉冲很棒 |
| Matrix | Arch layer 滑入 | 揭示 | 7 | 略平淡，可以考虑左右列**同时相对滑入**加强对照感 |
| Showcase | Marquee 3D tilt | 揭示 + 可交互提示 | 9 | 3D 入场很抓人 |
| 全局 | Cursor Spotlight + Grid drift | Ambience | 9 | 分寸感很好 |

**结构性建议（如果你想再往上推）：**
1. **Matrix 双列可以引入"竞争性"动效**：左列（DEEP）文字从下往上生长，右列（WIDE）从中心向左右扩张——语义上呼应"深度 vs 广度"
2. **Pipeline 可以加"输入物涌入 → 输出物溢出"的粒子**：现在的箭头脉冲是抽象点，如果换成小的文字标签（"业务需求"、"热点"）从左飘入 Forge 引擎再变成"图文"、"视频"标签溢出，就把"管道加工"具象化了
3. **Foot CTA 可以加一个"数字倒计时"或"当前访问人数+1"的微动效**，制造行动紧迫感

## 五、给你一个"启动新页面时"的 90 秒判断流程

以后拿到任何新内容，我按这个走：

```
1️⃣ 通读一遍内容 → 圈出"叙事高点"（3~5 处）
2️⃣ 每个高点问："这里在传达什么信息类型？"（用上面职能表 5 选 1）
3️⃣ 每个高点配一个"主动效"（不重复词汇）
4️⃣ 每屏配 1 个"背景动效"（ambience）
5️⃣ 检查：一屏是否只有 1 个主动效？stagger 时序是否合理？
6️⃣ 检查：所有动效方向是否语义同构？（增长向上、流失向下）
7️⃣ 检查：Reduced Motion 是否兜底？
```

---

**总的一句话哲学**：好的动效不是"这里能不能加点动画"，而是"**内容自己想动，我们只是把它显影出来**"。SmartForge 的 Leak Bar 就是这个思路的最好证据——"漏洞率 94%"这条信息本身就带着"应该被降下来"的叙事势能，动效不过是让这个势能可见。
