# 最优方案综合判断

> 定位：本文是调研体系的综合层——以七条最优标准为标尺，对每条标准给出辩证后的最优解法判断，并对照现状（`skills/html-pptx` v1.4 + `editor.html` v1.5）标出差距。
> 各项目的详细论证见 `projects/` 下细节文档；枚举层的规范见 `sota-visual-languages.md`。
> 索引：`source-survey.md` · 日期：2026-09-17。

## 0. 标尺与方法

七条最优标准（用户定义的目标态）：

1. 高/低文字密度双档下都能呈现比 guizang 更有设计感的幻灯片；
2. 动效丰富度可调，且各档都足够吸引眼球；
3. 支持复杂 fancy 信息图；
4. 支持复杂标注、复杂交互动效，全面覆盖各类图表；
5. 支持图片占位（占位图即换图指南）；
6. 双图片模式：a) AI 自主绘图作为插画 + 用户上传图；b) 纯 HTML/CSS 视觉 + 用户上传图；编辑时上传必须落盘到产物固定的 `assets/` 目录；
7. 图表、文字、信息图中的文字全部就地可编辑、可批注修改。

元原则：**整体原则要突出，枚举要谨慎**；凡是无法从原则推导、必须枚举的 SOTA 视觉语言，每个枚举项必须附带规则与验收标准，保证枚举可扩展。

方法：每条标准先指出其内在张力（做到极致会撞到什么），再给判断。判断分三层：原则可衍生的部分、必须枚举的部分、现状与差距。

## 标准① 密度双档 × 超越 guizang 的设计感

**张力**：密度越低越接近海报，容易"空"；密度越高越接近文档，容易塌成"标题+卡片墙"——后者正是 AI 的肌肉记忆。guizang 的解法是 22 个锁死版式，低密度下确实出彩，但锁死版式以压抑内容表达为代价换稳定，高密度长内容场景必然顶到天花板。

**判断**：

- 设计感的**身份层**（配色、字体配对、材质气质）不可从原则衍生，必须策展枚举——这是 guizang 真正做对的事，我们继承（主题库只选不改）。
- 设计感的**结构层**（比例、字阶、留白、节奏）可以原则衍生，且必须保持原则形态：容量先于版式、一页一个视觉重心、字重阶梯、密度双档冻结。这是我们能**超越** guizang 的空间——它的版式是枚举的，我们的版式由内容驱动，同一份 deck 不会出现构图雷同。
- 高低密度共用的底线是不溢出、不缩字号；分化的只是单页信息量与字阶取档（`references/typography.md` §5）。低密度靠"宁可加页"保住呼吸感，高密度靠结构化组件（grid/表格/Rowline）保住秩序感——两档的设计感来源不同，规则分别写清，不发明中间档。

**现状与差距**：骨架、主题库、typography 规范已到位。差距有二：① Step 5 渲染校验目前只有条文没有配套脚本，guizang 有静态校验 + Playwright 测量闭环（见 `projects/guizang-ppt-skill.md`），"比 guizang 更有设计感"首先要求校验不低于它；② guizang 字重阶梯的量化映射（≥8vw→weight 200、同页小字字重 ≥ 大字字重）比我们现行规则更硬，值得回填。

## 标准② 动效丰富度可调且各档吸睛

**张力**：动效越丰富越吸睛，但文本破坏性动效（拆字、逐字飞入）与就地编辑互斥，持续运行的氛围动效与性能、reduced-motion、iframe 嵌入场景冲突。

**判断**：

- 丰富度的正确载体是**语义 recipe 的组合密度**，不是动画机制堆叠：页面级 `data-animate` 定节奏、元素级 `data-anim` 定角色，档位 = 参与动画的元素比例与 recipe 复杂度。这套双层语义模型（源自 guizang，已在 v1.4 落地）是最优结构，无需推翻。
- 必须吸收 ppt-master 的一条反直觉原则：**自动触发的元素动画泛滥恰恰是 AI deck 的破绽**（`projects/ppt-master.md`）。吸睛靠的是入场编排的**节奏与次序**（何时出现、谁先谁后），不是持续扰动。因此"丰富"档 = 更多元素参与编排 + 更复杂的 recipe 编排，而不是给静态元素加循环动画。
- 拆字类禁用清单是正确红线（与标准⑦互斥，契约级，不可协商）。

**现状与差距**：`references/motion.md` 与骨架 `data-anim` 引擎已覆盖入场编排、降级链。差距：交互型动效（hover 微交互、点击展开的联动）尚无生成侧词汇，归入标准④一并判断。

## 标准③ 复杂 fancy 信息图

**张力**：信息图要 fancy 就要构图多样，但构图多样性与"枚举谨慎"直接冲突。

**判断**：信息图构图骨架是**有限可枚举集合**——ppt-master 归出 11 种几何骨架（并列/流程/中心辐射/象限/闭环/漏斗/金字塔/对比/时间线/地图/场景），guizang 的组件手册与之高度重叠。这不是巧合：内容关系的种类是有限的。因此：

- fancy 的上限来自**骨架组合 + token 演绎**，不来自新类型发明。一个"闭环+Stat 数字矩阵+Ghost 背景字"的组合页，视觉上远超任何单一组件，而规则只是三条已有枚举的叠加。
- `components.md` 的"内容关系 → 构图骨架 + 内容门槛"三件套是最优形态（已落地）：门槛规则（没有真实量化数据就不用量化组件）是反 AI-slop 的核心，保持硬规则地位。
- text_policy（图内嵌字 vs 文字外置）决定可编辑性，已入契约——这是标准③与标准⑦的接口。

**现状与差距**：12 个组件配方已覆盖常见关系。差距：复杂多层信息图（多层中心辐射、地图类、场景类）配方尚浅；缺**组合规则**——何时允许组件嵌套、嵌套时的容量预算怎么算，目前靠 AI 自由心证，应补一条原则级规则而非逐组合枚举。

## 标准④ 图表全覆盖 + 复杂标注与交互

**张力**：图表类型是开放集合，与"枚举谨慎"冲突；交互丰富与"零依赖、纯静态、可编辑"三条红线同时冲突。

**判断**（本条是七条中张力最集中的，分层拆开）：

- **覆盖策略 = 规则衍生 + 有限枚举**。规则层：数据→几何安全原则（先 clamp、防除零、防空数组）+ 系列色从主题 token 用 `color-mix` 统一推导——这层覆盖一切图表类型，包括没写配方的。枚举层：bar/line/donut/progress 四配方覆盖约八成真实场景。**新图表类型入库必须带完整规格**（配方 + 可编辑分层 + 验收），与 SOTA 枚举同规范，不允许"顺手发明一种图表"直接进入技能。
- **复杂标注 = 文字元素，不进几何**。标注、参考线标签、洞察文字一律是普通 `data-editable` 文字，定位在图表旁边而非画进 SVG——这样标注天然可编辑、可批注。图表的"insight 必须改写"硬规则（填数后结论文字要跟着改）保持。
- **复杂交互限定在零依赖范围内**：IO 触发入场、`:hover` 状态、`<details>` 类原生交互可以做；Chart.js 类运行时库明确拒绝（违反离线红线，且运行时生成的 DOM 绕过可编辑契约）。这个限制不是妥协，是形态自洽：我们的产物是**可编辑的静态文件**，不是应用。
- **可编辑分层是必须守住的诚实契约**：标签/图例可就地改，数值与几何绑定（改数走 AI 流程），SVG 几何整体 `data-editable-skip`。静态 HTML 做不到"改数字几何跟着变"，承认这一点比假装能做到更优——dashi 用同一路线（见 `projects/dashi-ppt-skill.md`）。

**现状与差距**：`charts.md` 四配方 + token 推导 + 契约分层已落地。差距：标注的定位配方（引线、角标、数值旗标）还没有组件化，复杂标注场景目前靠逐页现写，质量方差大——这是图表域下一迭代的最高优先项。

## 标准⑤ 图片占位

**张力**：占位图本质是"这里没有内容"，但用户的第一印象在它身上；做丑了用户抵触换图流程，做好看了成本高。

**判断**：占位图不是缺口的遮羞布，是**交付物的一部分**——它同时是构图说明书（尺寸即构图尺寸）、风格样本（主题色抽象图形）、换图指南（语义文件名）。open-design 的反面立场（统一要求 avoid placeholder images，真图走宿主生成，见 `projects/open-design.md`）恰好印证了：占位图若没有交付感设计，用户宁可不要占位。

**现状与差距**：占位图规格（主题色抽象 SVG、尺寸即构图尺寸、语义文件名）已在 SKILL.md 落地。差距：guizang 的 `data-image-slot` 三方绑定（槽位 ↔ 宽高比 ↔ 生成提示词，validator 静态强制，见 `projects/guizang-ppt-skill.md`）比我们多一层——我们的占位图没有显式槽位契约，AI 生图模式（标准⑥）落地时需要这一层，建议吸收。

## 标准⑥ 双图片模式（AI 生图插画 / 纯 HTML）

**张力**：两种模式看似两条产物线，处理不好会让技能分裂成两套流程。

**判断**：两种模式共享**同一条资产契约**——`assets/` 相对路径 + `data-editable-image` + 语义文件名 + 编辑器上传同名覆盖（已实现）。差异只在图片的**生产方式**，而生产方式是一条三级供给链，不是两种形态：

1. **纯 HTML 模式**：占位图即终态之一（主题色抽象 SVG），用户可换可不换；
2. **AI 生图插画模式**：AI 生成插画落盘 `assets/`（优先矢量风/可 SVG 化的风格，保证与主题 token 的色系统一），交付时已是"真图"，用户仍可替换；
3. **用户上传**：编辑器上传落 `assets/` 同名覆盖，或用户直接替换文件。

codex 的反降级契约（脚本强制禁止偷换渲染路径，见 `projects/codex-ppt-skill-main.md`）给生图模式一条必要纪律：声明了 AI 插画模式，插画就必须真实落盘并被引用（可静态校验），不允许用 CSS 渐变冒充插画。图片在嵌入态的保存走 postMessage（FSAA 不可用），编辑器已实现，与契约一致。

**现状与差距**：资产契约与编辑器上传已实现。差距：AI 生图插画模式本身（生图提示词规范、风格与主题 token 的对齐规则、落盘校验）尚未进入技能——这是七条标准里**唯一整条缺失**的能力，建议作为下一版本的主线，且落地前先把 `data-image-slot` 槽位契约（标准⑤）补齐。

## 标准⑦ 全要素可编辑可批注

**张力**：可编辑范围越大，生成侧标记负担越重；标记越细，产物 HTML 越浑浊。

**判断**：这条是本系统相对所有参考项目的差异化优势，也是现状最完整的一条——因为它在设计之初就是第一优先级，而不是事后补的：

- dashi 的标记契约、open-design 的两段手势与"文件即真相"、ppt-master 的 Annotate 双通道（标记写回 → AI 应用注解，见 `projects/ppt-master.md`），三家先行者的经验都已吸收进 `editing-contract.md` 与 editor.html。
- 图表分层、动效互斥两条契约级决断，把"什么不能编辑"与"什么不能动"说清楚了——可编辑性的上限不是技术问题，是诚实的边界声明问题。
- 批注不置脏、不进保存产物、三层引用（slide/path/excerpt），这个设计避免了批注污染交付物，判断正确，保持。

**现状与差距**：契约、就地编辑、图片替换、批注均已实现并有 harness 回归。差距主要是编辑器健壮性：open-design 七轮实测迭代的坑清单（contenteditable 释放 line-clamp 导致选中变大、粘贴必须传字节防 `ERR_UPLOAD_FILE_CHANGED`、undo 原地化、Home/End 滚底等，见 `projects/open-design.md`）是 editor.html 后续迭代性价比最高的避坑清单。

## 总体结论

| 标准 | 最优解法（一句话） | 主要来源 | 现状 | 关键差距 |
|---|---|---|---|---|
| ① 密度×设计感 | 身份层枚举（主题库）+ 结构层原则（容量/字阶/密度档） | guizang + frontend-slides | 已落地 | 渲染校验脚本化、字重量化回填 |
| ② 动效分档 | 丰富度 = 语义 recipe 组合密度；吸睛靠编排节奏不靠持续扰动 | guizang + ppt-master | 已落地 | 交互动效词汇（见④） |
| ③ 信息图 | 有限骨架枚举 + 组合原则 + 内容门槛 | ppt-master + guizang | 已落地 | 多层复杂图配方、组合规则 |
| ④ 图表+标注+交互 | 规则衍生打底 + 四配方枚举；标注=文字不进几何；交互限零依赖 | dashi + guizang | 配方落地 | 标注组件化是下一最高优先 |
| ⑤ 图片占位 | 占位图即交付物（构图说明+换图指南） | 本项目原创 + guizang | 规格落地 | 补 `data-image-slot` 槽位契约 |
| ⑥ 双图片模式 | 一条资产契约 + 三级供给链（占位/生图/上传） | 本项目原创 + codex 纪律 | 契约落地 | AI 生图模式整条待建 |
| ⑦ 可编辑可批注 | 标记契约 + 诚实的能力边界声明 | dashi + open-design + ppt-master | 最完整 | 编辑器实测坑清单迭代 |

## 元原则判定：哪些能衍生，哪些必须枚举

| 层 | 判定 | 理由 |
|---|---|---|
| 密度、字阶、容量、行高 | **原则可衍生** | 有数学性不变量，渲染测量可闭环验证 |
| 一致性机制 | **原则可衍生** | token 系统承载，一条原则足够 |
| 数据→几何安全 | **原则可衍生** | clamp/防除零是普适规则 |
| 主题视觉语言（色/字/材质） | **必须枚举** | 文化性知识，无函数可算，AI 默认分布收敛平庸 |
| 信息图骨架、图表配方、动效 recipe | **必须枚举** | 有限集合，枚举是保护不是枷锁 |
| 页面版式构图 | **禁止枚举** | dashi 1020 模板是前车之鉴；版式由内容驱动 |

凡属"必须枚举"的层，每个枚举项按 `sota-visual-languages.md` 的规范携带规则与验收标准——这是枚举可扩展的唯一保障。
