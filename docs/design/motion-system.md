## 1. 核心裁定：拆字与就地编辑不互斥

v1.4 的契约是"拆字类动效一律禁止"（理由：拆成 `<span>` 后 contenteditable 编辑体验崩坏）。用户裁定：**不要为了编辑降低动效标准**——拆字可做的效果是动效天花板的重要组成部分（shatter/split-char 类），编辑粒度下沉到字符级即可。

### 架构决定：拆字从"生成时"移到"运行时"

| | 生成时拆分（v1.4 假设的形态） | **运行时拆分（本设计）** |
|---|---|---|
| 文件中的文字 | 一堆 `<span>` 字符碎片 | **纯文本节点** |
| 编辑器看到 | 碎片 DOM，编辑即崩 | 纯文本，现有编辑逻辑零改动 |
| 保存产物 | 碎片污染文件 | 序列化天然干净 |
| 无 JS / reduced-motion | 需额外降级代码 | **天然降级**（文件里本来就是纯文本） |

机制：

1. 生成侧只写纯文本 + 语义标记：`<h1 data-anim="chars">标题文字</h1>`——**产物文件里永远不出现拆字 span**；
2. 骨架 JS 升级（skeleton v3，与 `theme-schema.md` 的质感槽位同版发布）：对 `data-anim="chars" / "words"` 的元素，入场时把 `textContent` 拆成 span 序列执行动画，动画完成后**还原为纯文本节点**（避免长期持有碎片 DOM）。滚动回滚再次入场的行为：**默认不重复触发**（与现有 `.reveal` 一次性语义一致）；需要重复入场的 recipe 必须显式声明，且重复触发前先还原再重拆；
3. 编辑器序列化净化清单新增一条：若遇未还原的拆字 span 容器（动画进行中被打断），还原为 `textContent` 再保存。**用户在动画进行中点击进入编辑时，编辑器先强制还原该元素为纯文本再进入编辑态**；
4. 编辑该元素时就是编辑一个纯文本 `data-editable` 元素——与现有契约完全一致；**编辑后动画不失效**，下次入场重新按新文本拆分。

这同时解决了 v1.4 禁令的三个隐患：编辑冲突（不存在了）、降级代码（不需要了）、产物浑浊（文件始终干净）。`editing-contract.md` 的"拆字禁令"条款修订为：**文本破坏性动效必须运行时化——产物文件中的文字永远是完整纯文本节点，拆字/变换只允许由骨架 JS 在运行时进行**。

## 2. 原理层：三条物理原理（写入 motion.md v2 的原则区）

直接采纳 motion_gudie.md 的三条底层原理，它们是"能不能动"的硬约束：

1. **动效是注意力预算**：一屏最多 1 个主动效（叙事驱动、大幅变化、>600ms）+ 2–3 个背景动效（呼吸/漂移/扫描线，不承载信息）。超过即"哪儿都在动等于哪儿都没动"。→ 升为【硬规则】，渲染验收可静态检查主动效计数。
2. **动效必须承担信息职能**：合法职能只有五种——揭示存在（entry）/ 传达数据变化（transform）/ 建立空间因果（causality）/ 指示可交互（affordance）/ 维持存在感（ambience）。**归属两种以上 = 过重，删掉**。这给了"该不该加动效"一个可判定的标准，也是动效版的"一页一意"。
3. **时长匹配信息密度**：`时长 ≈ 300ms + 信息比特 × 200ms`。fade 一个标签 300ms，slide-in 一张卡 500ms，count-up 一个数字 1200–1800ms，shatter 一个标题 ~1800ms，循环动效 ≥3s 越缓越高级。fade 慢到 1s、count-up 快到 500ms 是最常见翻车点。→ recipe 配方里的时长按此取档。

## 3. 组合层：六条原则（写入 motion.md v2 的默认区）

1. **编舞（stagger）**：同类元素永不同时动；步长 ≈ 单元素时长 / 元素数 × 1.2。
2. **三段式**：Reveal → Hold（≥1500ms 静止期，不可省略）→ Interact；背景动效不得占用静止期的注意力（粒子密度、呼吸幅度压到极低）。
3. **锚点动效**：每页主角配一个**独有**的动效变体（其他元素用常规款），让用户记得住这一页——与"一页一个视觉重心"原则同构。
4. **词汇表纪律**：一份 deck 只用 2–3 种缓动函数（进 `cubic-bezier(.22,1,.36,1)` / 变 `cubic-bezier(.7,0,.2,1)` / 循环 `ease-in-out`），写进骨架 token，禁止逐页自定义。
5. **方向语义同构**：增长向上向右、流失向下降饱和、流程从左到右、稳定几乎不动。动效方向与内容语义冲突即失败。
6. **感知性能**：入场动效本身占用注意力、让加载感变短；但骨架/首屏 200ms 内必须可见。

一句话哲学（保留原文，作为 motion.md 的开篇）：**好的动效不是"这里能不能加点动画"，而是"内容自己想动，我们只是把它显影出来"**。

## 4. 词汇层：动效 recipe 扩展（枚举，带规则）

v1.4 只有 fade/slide/blur/scale/逐行 等文本安全款。v2 按 motion_gudie 的"内容→动效"对照表扩展为完整词汇表，每个 recipe 是枚举项，按 sota-visual-languages.md 七件规范入库：

| recipe | 信息职能 | 适用内容 | 时长档 | 实现要点 |
|---|---|---|---|---|
| `chars` 逐字飞入 | entry（强调） | 封面/章节标题 | ~1800ms | **运行时拆字**（§1） |
| `shatter` 碎聚 | entry（最强） | 全 deck 仅首页主角 | ~1800ms | 运行时拆字 + 散布聚合；一份 deck 限 1 次 |
| `count-up` 数字滚动 | transform | 大数字/KPI | 1200–1800ms | 运行时读取 `data-editable` 文本终值，从 0 或 `data-from` 起滚；文本仍是纯文本 |
| `draw-line` 描绘 | causality | 流程连线/箭头/图表折线 | 800–1500ms | stroke-dasharray；几何元素 `data-editable-skip` |
| `fill-bar` 填充 | transform | 进度/占比/横条图 | 800–1200ms | scaleX 从 0 到目标宽度 |
| `stagger-*` 系列 | entry | 卡片/列表/网格 | 单项 300–500ms | 编舞步长按 §3.1 公式 |
| `pulse` / `drift` / `glow` | ambience | 背景层/水印/呼吸点 | ≥3s 循环 | 只允许背景层；密度与幅度有上限 |
| `morph-arrow` 等交互款 | affordance | hover/焦点态 | ≤300ms | CSS :hover 即可，不进 JS |

丰富度档位（design-system 面板 motion 选项）= **主动效编排复杂度 + 背景动效有无**三档：克制（仅 entry，无背景）/ 标准（entry + 1 锚点 recipe + 1 背景）/ 华丽（锚点 shatter/count-up 级 + 背景 ambience + 交互 affordance）。**三档共享注意力预算硬规则**——丰富度加的是编排层次，不是同时动的数量。

## 5. 与编辑/图表/主题的接口

- **编辑**：所有文本类动效运行时化（§1）；`data-anim` 属性本身不参与编辑，编辑器忽略；编辑后重入场重拆字，动画跟随新文本。
- **图表**：`draw-line`/`fill-bar`/`count-up` 即图表入场动效的标准款，图表 recipe 不再单独定义动画（charts.md 引用本词汇表）。
- **主题**：主题 Schema G5 声明动效亲和与禁用（如 C4 纸与墨禁 shatter、A 系倾向慢时长档），生成侧选型时遵守。
- **reduced-motion**：所有动效消失且内容完整可读（现有红线不变）；运行时拆字方案下这条零成本成立。

## 6. 验收标准

- **机器可验**：产物 grep 无拆字 span（`<span>` 内单字符且父元素带 data-anim 的模式 = 违规）；每页主动效 recipe ≤1；缓动函数白名单 ≤3 种。
- **渲染可验**：Playwright 注入 `prefers-reduced-motion` 后全文本完整可读；动画完成后 DOM 中无残留拆字 span（还原检查）；编辑往返后 `data-anim` 元素幂等。
- **人工可验**：90 秒流程走一遍（圈叙事高点 → 五职能归类 → 每页 1 主动效 → 语义方向检查），样张页评审"记得住"测试。
