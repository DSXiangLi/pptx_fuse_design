## 1. 核心裁定：插画是内容验收后的独立 pass

用户裁定：AI 生成插画**不与内容生成同步进行**，而是 HTML 版式内容验收通过后，由 AI 统一补齐。

理由（设计确认）：

- 内容未定稿前生图是浪费——改文案换构图后插画作废，且生图成本远高于排版；
- 验收后统一补齐有**全局一致性收益**：AI 拿着完整的页计划表和冻结的主题，一次性规划全部插画的风格、色系、视角，避免逐页生图的气质漂移；
- 与三级供给链（占位 → AI 插画 → 用户上传）天然兼容：插画 pass 就是把"占位"批量升级为"AI 插画"的那一个环节。

## 2. 工作流修订

```
Step 0-5（现状不变）：输入 → 页计划表 → 冻结主题 → 骨架 → 逐页生成 → 渲染校验
        产物 = 内容版 deck（全部图片位为主题色抽象占位图）
Step 5.5【新增】内容验收确认 → 用户选择图片模式：
        a) 保持纯 HTML 模式（占位图即终态，结束）
        b) AI 插画模式 → 进入插画 pass（本文档）
Step 6（现状不变）：交付
```

插画 pass 内部分四步：

1. **盘点槽位**：扫描全 deck 的 `data-image-slot`，产出插画清单（槽位 / 页面 / 比例 / 内容意图）；
2. **风格规划**：按主题 Schema G7 字段（插画风格描述 + 提示词种子 + 禁忌）+ 主题 token 色系，写出全 deck 统一的插画风格段（一段文字，所有槽位共享）；
3. **逐槽生图**：每槽位的提示词 = 统一风格段 + 槽位意图 + 比例规格；生成落盘 `assets/`，**同名覆盖占位图**；
4. **回归校验**：渲染校验重跑一遍（图片比例不符会导致布局偏移）；反降级校验（§4）。

## 3. 图片槽位契约（吸收 guizang `data-image-slot`）

现状的图片标记只有 `data-editable-image`，占位图规格靠文字纪律约束，机器不可验。升级为槽位契约：

```html
<img data-editable-image
     data-image-slot="cover-hero-21x9"
     data-image-intent="团队协作的抽象场景，暖色调，俯视"
     data-image-state="placeholder"
     src="assets/cover-hero.svg" alt="…">
```

- `data-image-slot`：语义名 + 宽高比（`21x9`）。**槽位决定构图尺寸，构图尺寸决定生图比例**——三方绑定，静态可验（img 的容器宽高比 vs 槽位声明比例）；
- `data-image-intent`：内容意图一句话。占位图阶段是生成占位图形的依据，插画 pass 阶段是生图提示词的槽位部分，用户换图时是换图指南；
- `data-image-state`：图像供给状态机（`placeholder` → `generated` → `uploaded`），反降级校验的依据（§4）；
- 编辑器上传替换时**保留 slot 与 intent 属性**（只换 src 指向的文件），并把 state 置为 `uploaded`——契约不随换图丢失。

pptx 转换入口的图片同样落槽位：提取的原图保持原样落盘，AI 按画面角色补 `data-image-slot` 与 `data-image-intent`。

## 4. 反降级校验（吸收 codex 经验）

声明 AI 插画模式后，必须防止"AI 偷懒不生成、用 CSS 渐变或占位图冒充插画"：

- **机器可验**：声明插画模式的 deck，每个 `data-image-slot` 必须存在对应的 `assets/` 落盘文件且被引用。图像状态用显式属性而非内容指纹判定：占位图带 `data-image-state="placeholder"`，插画 pass 落盘后改为 `"generated"`，编辑器用户上传后改为 `"uploaded"`——插画模式产物中出现 `placeholder` 状态的槽位 = 违规（比"识别占位图视觉指纹"可靠得多）；
- 生成失败的槽位**诚实回退**为占位图（保持 `placeholder` 状态）并在交付说明中列出（回退不是失败，冒充才是）。

## 5. 插画风格与主题的对齐

- 主题 Schema G7 给出该主题下的插画风格种子（如 B 系瑞士风 → 扁平矢量、单 accent 点缀、禁止写实照片风；C2 暗夜植物园 → 暗底暖光插画）；
- 主题未声明 G7 时走缺省推导：主题色抽象图形的精细化版本（与占位图同族，视觉连续）；
- 插画**不改布局**：尺寸即构图尺寸的纪律不变，生图只填槽位，不重排页面。

## 6. 与编辑器/嵌入态的关系

- 插画 pass 的产物与普通 deck 无差别：编辑器照常用 `data-editable-image` 替换图片，上传落 `assets/` 同名覆盖；
- 嵌入态下插画 pass 的产物经 postMessage 正常流转（无新增协议）；
- 用户上传永远是终态：上传的图不会被后续 AI 操作覆盖（编辑器只写用户显式选择的文件）。

## 7. 验收标准

- 机器可验：槽位契约完整性（每个 `data-editable-image` 有 slot + intent）；比例绑定（容器宽高比 = 槽位声明比例，容差 5%）；反降级指纹检查；
- 渲染可验：插画 pass 前后两次渲染校验均通过（图片替换不引起溢出）；
- 人工可验：全 deck 插画气质一致（同一风格段的执行质量）；插画与主题的色系协调；样张评审。

## 8. 明确不做

- 不做逐页即时生图（与内容生成解耦是本设计的核心，不走回头路）；
- 不做页面内的"重新生成此图"按钮（页面内无 AI，重新生图走 coding agent 流程）；
- 不承诺照片级写实插画的版式自适应——插画只填既有槽位，不为插画改构图。
