## 四、补充调研结论（baoyu-design + html-ppt-skill 新资产 + 存量复查）

`source/` 新增项目：`baoyu-design/`（Anthropic Claude Design 系统提示词的 Skill 化打包，dashi 的艺术指导来源）与 `html-ppt-skill/`（lewislulu 的 HTML PPT 工作室技能，36 主题 + 15 全 deck 模板 + 27 CSS/20 canvas 动效）；frontend-slides plugins/ 是重新打包零新内容；ppt-master 的 `examples/`（21 个完整 deck 的 spec_lock）是此前被低估的资产。

可借鉴的四件（baoyu-design，详见调研，引用从略）：

1. **VISUAL FOUNDATIONS 完备性问卷**：一个主题必须回答完——颜色/字体/间距/**背景形态/动效性格/hover 与 press 态/边框与阴影系统/透明度与模糊/图像色彩气质/圆角与卡片长相**——才算被描述。正中我们"质感层/装饰层/容器层缺失"。
2. **差异轴纪律**：每个候选项必须说得清"在哪条轴上与其他不同"——同一想法的五个深浅不是选择。
3. **unforgettable 一问**：每个风格方向必须回答"这套设计让人记住的那一个东西是什么？"
4. **ppt-master examples/ 的 21 份 spec_lock**：Memphis 糖果流行、brutalist 报纸、risograph 孔版、蓝图、植物染传统色、玻璃拟态……21 个"强主题如何落成机器可读契约"的实战锚点。

html-ppt-skill 的四件增量（对课题一直接命中）：

5. **主题双层架构**：36 套轻量 token 主题（每套 15-27 行 CSS，但约一半会追加 2-5 条"越界选择器"承载质感层/容器 DNA/字排签名——retro-tv 的 CRT 扫描线、news-broadcast 的硬投影卡片、japanese-minimal 连页边距都是主题级）+ 15 个重主题 full-deck 模板（`tpl-<name>` 前缀隔离的 40-216 行 scoped CSS，装饰母题全在这层；README 固定三段式：Source inspiration / Key visual traits / When to use——可当我们主题 Schema 的扩展原型）。**警示证据：它那 15 行纯调色板主题就是"只有色+字"的下场——我们的 20 主题若没有质感/容器/字排层，会收敛成同一种东西**。
6. **撞脸检测装置**：`theme-showcase.html` 把 36 个主题各装进 iframe 渲染**同一份内容**供肉眼 diff——20 主题 ×3 配色的差异化验收就缺这个机制，可直接照搬进 gallery/。
7. **主题热插拔 audition**：主题是独立 CSS 文件 + `data-themes` 白名单 + T 键循环试穿——"生成前冻结"之外的另一种决策时机，是 design-system 面板可视化候选的低成本形态参照。
8. **语义化 FX**：knowledge-graph（力导图）/neural-net（脉冲沿边传播）/chain-react（多米诺脉冲=pipeline）/counter-explosion（count-up+粒子爆发）——动效承载内容隐喻，是想象层隐喻库的现成候选（我们的 canvas fx 四款目前全是氛围装饰）。

另外确认：**内容→呈现的发散机制在所有已调研项目中都不存在**（html-ppt-skill 也是收敛式查表，只有"同版式不连用"的否定纪律）——想象层没有先行者，是我们自己的设计空间。

## 五、独立思考：对新问题的回答（慎独部分）

### 5.1 为什么三个 v3 依然像一种风格——趋同的真正结构

用户观察准确。根因不是"主题不够多"，而是：**当前主题只拥有"色与字"两个维度的主权，其余一切（装饰语言、容器形态、动效行为、构图引力）都是骨架共享的默认值**。而我们 F1–F6 的装饰语言（hairline、Ghost 字、mono 刊头、裂屏、绘线入场）恰好全部学自归藏——于是所有主题都长在归藏杂志风的骨骼上。换色换字不换骨，观感自然都是"杂志风割"。

**推论：主题差异化的定义必须改写**——主题 ≠ 配色方案。主题是一个**七层表达力栈**，每层都要有主权：

| 层 | 内容 | 现状 |
|---|---|---|
| L1 色彩系统 | 3+ 配色变体（见 5.3） | ✅ 有 |
| L2 字体性格 | 配对 + 字重性格 + 字号对比度 | ⚠️ 有但趋同 |
| L3 **质感层** | 材质（纸纹/颗粒/扫描线/玻璃/布纹……） | ❌ 名义有实质缺（token 有了但装饰语言没跟上） |
| L4 **装饰母题** | 每个主题自己的装饰词汇（不是全都用 + 号和 hairline：risograph 用套色错位、蓝图用标注引线、Memphis 用几何碎形……） | ❌ 缺失——这是"底部都是加号"的病根 |
| L5 **容器风格** | 卡片/面板的造型语言（直角/圆角/撕边/描边/叠印/玻璃……） | ❌ 缺失 |
| L6 **动效签名** | 主题独有的节奏与 recipe 倾向（editorial 的慢淡入 vs brutalist 的硬切 vs playful 的弹跳） | ❌ G5 只有禁用清单，没有签名 |
| L7 **构图倾向** | 谱系偏好与禁忌（宣言系偏爱巨字、数据系偏爱图表英雄……） | ❌ 缺失 |

**两个主题在 7 层里至少 3 层实质分化，才算两个主题**——这就是 20 主题入库的可检查门槛（对 baoyu"差异轴"纪律的具体化）。

### 5.2 想象层：内容 → 呈现的发散机制

用户点名的"所有柱图都增长、数字都 count-up、对比都是左右、流动都是箭头"，病根是**隐喻库只有一格**。同一内容关系有大量视觉隐喻，AI 默认收敛到最平庸的那个。解法是两个机制：

1. **工作流插入发散步**：SKILL.md 的逐页生成前，对每个关键内容块先写 **3 个不同轴上的呈现方案**（必须命名差异轴：尺度/隐喻/维度/动静/材质），再选定。这步不进产物，进页计划表的一列。
2. **隐喻库（motif library）**：为常见内容关系枚举**发散的视觉隐喻**，每个隐喻绑定视觉语言与适用主题气质——对比：裂屏/天平/拔河/赛道/镜像/前后对照；增长：柱上升/阶梯/年轮/潮汐线/藤蔓；流程：管道/河流/接力/渗透/循环；数字呈现：count-up/翻牌/刻度盘/仪表/印戳。枚举纪律不变（七件规范），但枚举的对象是**隐喻**而非版式——这是发散层该枚举的东西。

### 5.3 灵感来源：新主题如何被构思（核心问题）

我的主张：**主题不是配出来的，是从"世界"里采样翻译出来的**。20 个鲜明主题 = 20 个世界参考。灵感来源的分类学（采样轴）：

- **材质与工艺**：risograph 孔版（套色错位+颗粒）、丝网印、活字印刷、蓝晒/蓝图、搪瓷标牌、刺绣、宣纸水墨、黑板粉笔；
- **媒介与时代**：装饰艺术 Art Deco、60s 瑞士海报、90s 终端 CRT、VHS 录像带、报纸排版、植物标本图鉴、工程图纸、像素艺术、Y2K；
- **文化与地域**：包豪斯、苏联构成主义、日本杂志（BRUTUS 系）、Memphis、植物染传统色（ppt-master 已有李子柒样本）、浮世绘；
- **自然系统**：地质岩层、深海、苔藓、星图、气象图；
- **行业语言**：证券行情终端、建筑蓝图、乐谱、地图制图、实验室记录、登机牌/票据。

**每个主题的构思流程**（六步，全部落在七件规范上）：

1. **选世界参考**：一句话说清它是什么（"1950 年代瑞士铁路时刻表"）；
2. **unforgettable 一问**：这套主题让人记住的一个东西是什么（"时刻表翻牌"）——答不上来就不立项；
3. **七层翻译**：把那个世界的材质/色彩/字体/装饰母题/容器/动效/构图逐层翻译成 token 与规则。**忠实度是关键**——risograph 主题必须有套色错位和颗粒噪点，不是换个粉蓝色就叫 risograph；
4. **3 套配色变体**：同一世界的不同"光线/时辰/材质"演绎（蓝图的白线蓝底/蓝线白底/黑板粉笔），不是三个不同主题；
5. **反例与禁忌**：这个主题最忌讳什么（蓝图主题忌圆角和阴影）；
6. **验收样张**：一张封面 + 一张数据页 + 一张信息图页，进画廊回归。

**采样清单的现成锚点**：ppt-master examples 21 份 spec_lock（直接可翻译）、open-design 的 154 品牌 design-systems、编辑设计史。20 主题目标建议分两批：第一批 10 个把采样轴拉开（每轴 1-2 个，保证两两 3 层分化），第二批 10 个补密度。

**html-ppt-skill 的双层架构对建库形态的影响**：主题库应分两级——**重主题**（带质感层/装饰母题/容器 DNA/动效签名的完整七层主题，对应其 full-deck 模板层，README 三段式：Source inspiration / Key visual traits / When to use）与**轻主题**（token 级配色变体，承载"每主题 3 套配色"）。20 个鲜明主题指重主题；配色变体是轻量级的，不稀释差异化。它的教训同样要写进入库门槛：36 主题里 15 行纯调色板的那一半，正是没有质感/容器/字排层的下场。

### 5.4 落地路线建议（下个 session 的迭代序列）

1. **G 期 · 主题表达力栈**：themes.md Schema 从 G0–G8 扩到七层（L3 质感/L4 装饰母题/L5 容器/L6 动效签名/L7 构图倾向为新增重点）；骨架/组件提供装饰母题与容器风格的机制支持（母题=每主题一组装饰件 CSS 类 + 动效签名=主题级 recipe 参数覆盖）；存量 16 主题补七层（或宣布其中趋同的退役合并）；
2. **H 期 · 隐喻库 + 发散步**：components.md 或新 references/motifs.md；SKILL.md 工作流加呈现发散步；html-ppt-skill 的语义化 FX（knowledge-graph/neural-net/chain-react/counter-explosion）是隐喻库的现成候选——动效承载内容隐喻，而非只做氛围；
3. **I 期 · 20 主题建库**：按 5.3 流程分批构思，每主题 3 配色 + 样张进画廊；验收 = 两两 3 层分化声明 + **撞脸检测装置**（照搬 html-ppt-skill 的 theme-showcase：同一份内容装进全部主题的 iframe 矩阵页，肉眼 diff，撞脸立现）；

### 5.5 诚实声明（给下个 session 的提醒）

- 20 个"鲜明"主题的难度不在枚举在**忠实翻译**——risograph 没有套色错位就是骗子主题。每个主题的美术考据成本是真实的，宁缺毋滥；
- 装饰母题进骨架有膨胀风险：建议母题走"主题 token + 主题自带 CSS 块"（SLOT 注入）而非框架层硬编码；
- 想象层发散步会增加生成成本，建议只对"关键页"（封面/数据页/对比页）强制，普通页豁免；
- 差异化验收目前没有自动化手段（"一眼不同"是人工判断）——可以接受，但每主题的三层分化声明是机器可查的底线。
