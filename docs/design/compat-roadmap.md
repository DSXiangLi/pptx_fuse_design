# 上下兼容设计（未来规划：全图化与 html2pptx）

> 状态：**已被取代** · 2026-09-21 由 `tri-form-architecture.md` + `page-render-mode.md` + `pptx-export-svg.md` + `editor-tri-view.md` 取代为实施级设计（主要变化：全图化收敛为整页 AI 烙入唯一形态、html2pptx 改走 PDF→SVG 矢量管线、新增 manifest/content-hash 公共地基与编辑器三态对比）。本文档保留作历史记录。
> 依据：2026-09-18 修订意见 7 · 定位：**未来方向规划**，不进入当前迭代范围（第一期仍是 HTML 页面化编辑）
> 前置依赖：`illustration-pipeline.md`（生图能力）、渲染测量工具链（Playwright 截图即全图化的技术底座）。

## 1. 总原则：HTML 永远是唯一事实源

向上（全图化）与向下（pptx）都是**导出态分支**：从 HTML 主分支派生，不反向污染主分支。任何时候用户回编辑流程，面对的仍是 HTML deck。这与"文件即真相"原则一致——分支产物可再生成，主分支不可替代。

## 2. 向上兼容：页面级全图化

### 场景与触发

HTML 版式效果满意后，用户希望部分页面有超越 HTML/CSS 表现力的视觉（电影感插画页、复杂材质封面）。用户**选定若干页**转为全图页。

### 两档全图化

| 档 | 机制 | 适用 |
|---|---|---|
| 截图档 | 无头浏览器按 1920×1080 渲染该页截图，PNG 落 `assets/` | 保真固化：版式满意、只为免疫字体/环境差异 |
| 重绘档 | 截图为底稿，AI 基于截图 + 该页内容意图重新绘制（构图继承、表现力升级） | 视觉升级：封面、章节页、情绪页 |

### 产物形态：混合 deck

- 全图页在 deck 中变为 `<img data-editable-image data-render-mode="raster">` 整页填充；未转换页保持 HTML。**一份 deck 内 HTML 页与全图页混合**，滚动/缩放/键盘导航不变；
- **原页 HTML 以注释形式嵌入保留**（`<!-- raster-source: <section …> … -->`）：回退 = 还原注释。嵌入时原 HTML 中的 `--` 序列必须转义（HTML 注释内不允许出现 `--`），还原时反转义——这条写进转换工具的实现规约；批注对全图页仍可用（批注框选不依赖文字可编辑，但全图页的 excerpt 为空、引用粒度只有页级 + 坐标区域，写进批注导出格式说明）；
- 全图页的文字不可就地编辑——**诚实声明**：这是用户用编辑性换表现力的显式选择，转换操作必须逐页确认，不做"一键全 deck 全图化"的默认推荐；
- 保存格式：deck 仍是单 HTML + assets/（全图页的图片在 assets/ 内）——"全部图片"的诉求由"全选所有页转换"满足，文件形态不变。

### 风险与对策

- 全图页在窄窗口/打印下的行为与 HTML 页一致（同一个 `.slide` 容器与缩放骨架），无新增适配负担；
- AI 重绘的图文一致性：重绘提示词必须包含该页全部文字内容（文字渲染进图），验收走人工样张评审——位图中的文字不可校验，这是全图页的固有代价，写进交付说明。

## 3. 向下兼容：html2pptx

### 定位与保真天花板

把 HTML deck 中能兼容的部分落成原生可编辑 pptx。保真天花板有明确证据（Slidev `pptx-editable` 实践，见 `../research/source-survey.md` §五），因此设计目标不是"高保真还原"，是**分层映射、诚实降级**。

### 三层映射策略

| 层 | 内容 | 映射 |
|---|---|---|
| 原生映射 | 文本框（标题/正文，字阶按比例换算 pt）、图片（assets/ 直接嵌入）、简单色块/分割线 | → pptx 原生元素，可编辑 |
| 结构降级 | 信息图（结构族×皮肤）、四配方图表 | → 优先映射为 pptx 形状组合；映射不了的整组件渲染为 PNG 贴入 |
| 整页降级 | 复杂动效页、运行时拆字页、质感叠加页 | → 整页渲染截图贴入 pptx |

- 逐页产出映射报告（哪些元素原生、哪些降级为图），不给"100% 可编辑 pptx"的承诺；
- 主题 token 映射为 pptx 的主题色/字体设置，保证原生元素在 pptx 里仍可统一换肤。

### 工具形态

独立脚本/技能（如 `scripts/html2pptx` 或独立技能），**不进产物、不进 editor.html**——产物纯净性红线不变。技术上基于 python-pptx 或 pptxgenjs，输入是 HTML 文件 + assets/。

## 4. 排序与依赖

```
插画管线（illustration-pipeline）
   ↓ 生图能力成熟、assets 契约稳定
向上兼容（全图化）—— 截图工具链与渲染校验共用
   ↓ 截图/渲染基础设施复用
向下兼容（html2pptx）—— 三层映射中的"降级为图"复用截图链
```

理由：插画管线建立生图纪律与槽位契约；全图化复用渲染截图工具且风险局部（逐页可选）；html2pptx 工程量最大、保真天花板最低，放最后。每一步独立可用，不做大爆炸式开发。

## 5. 验收标准（规划级）

- 全图化：混合 deck 过 harness 回归（滚动/缩放/保存幂等）；全图页注释还原回退可用；批注对全图页可用；
- html2pptx：映射报告准确率（抽页核对原生/降级判定）；原生文本在 PowerPoint 中可编辑可改字；降级页截图清晰（1920×1080 渲染分辨率）；
- 两者共同：主分支 HTML 文件在两次导出前后字节不变（导出只读主分支）。
