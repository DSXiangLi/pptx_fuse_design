# Learnings：HTML→可编辑 PPTX 导出踩坑复盘

> 来源：2026-09-22～29 三形态子技能 C（可编辑导出）从首版到"三零"（容量 0 / 认证 0 / 降级 0）的完整踩坑史。
> 读者：后续维护导出管线、或做任何"浏览器渲染 → OOXML 转录"类工作的 agent。
> 每条 = 现象 → 根因/误判 → 正解 → 预防规则。证据与过程细节见 `docs/progress/0924_editable_overlap_fix.md`。

## 〇、五条通用原则（本轮最大的认知产出）

1. **视觉 QA 不可信赖，数学认证才是出厂依据**（用户原则，2026-09-28）：文本重叠/边距问题在写入 pptx 后可以直接读结构化 XML 纯计算认证（逐行墨水宽、逐块墨水高、墨水盒相交），不需要渲染。渲染回验（LO 截图 diff）降级为参考通道。
2. **"HTML 装得下 ≠ PPT 装得下"**：Chromium 与 OOXML 的文本度量不同构（混排间距、行高口径、断行规则全不同）。容量约束必须用 PPT 度量口径**前置到 HTML 搭建期**（check-capacity 生成侧门禁），不能指望导出侧补救。
3. **同一套数学贯穿四环**：生成侧容量预算、导出布局定型、产物认证、回归断言共用同一个度量模块（pptx_text_metrics.py）——两处各写一份度量逻辑必然漂移（我们为此付出过一轮 16 页假降级的代价）。
4. **度量常数必须用受控实验钉死，禁止单次反推**：混排间距第一版"1.04em"是单行文本反推的误算（真实值 0.25em，受控实验 + 文献双重印证）。错误常数比没有常数更糟——它把修复环逼进打地鼠振荡。
5. **降级兜底机制不是罪过，假降级才是**：页级降级矢量件是诚实的最后出路；但当兜底被频繁触发，先怀疑上游模型错了，而不是内容真的装不下。

## 一、文本框与行模型

| # | 坑 | 根因 | 正解 |
|---|---|---|---|
| 1 | 逐渲染行 a:p + 紧配合框，PowerPoint 里大面积重叠 | 行距/断行口径差异逐行累积下溢（slide-paipai README 记载过同款失败） | 单行/标题 wrap=none 永不重排；多行逻辑段 a:p（硬换行分段、软换行交 PPT 贪心重排）；框高 +1 行松配合 |
| 2 | lnSpc 写精确磅值（spcPts），字体一换就叠字 | 精确磅值不随字体缩放；PPT 精确行距 < 字体自然行高时行内叠字 | lnSpc 一律 spcPct 相对口径，≥ 候选字体集最坏自然行高 ×1.03 |
| 3 | 行距校准"放大到自然行高"导致多行块整体下溢压邻居 | 只抬行距不重预算块高 | 块高 = Σ实际行距重新预算；装不下用 normAutofit 缩字（2% 步进、下限 0.85），不硬压行距 |
| 4 | hhea ascent/descent 当墨迹高度用，mend-bar 类紧排被误报碰撞 | hhea 是行距储备不是墨迹 | 墨迹用 OS/2 typo 口径；行距储备用 hhea——两者分清 |
| 5 | 首行基线系统性偏移 | 未按字体 ascent 补偿 | 文本框 top 按 CSS 半行距补偿（slide-paipai 的 y−5px 同款思路，用真实字体度量算） |

## 二、宽度与混排

| # | 坑 | 根因 | 正解 |
|---|---|---|---|
| 6 | 高密度金融文本在 PPT 里提前换行、块底下溢 | **OOXML 中西文混排自动间距**（CJK↔拉丁边界 +0.25em/对）完全没建模 | 宽度模型加边界项（`MIXED_BOUNDARY_EM=0.25`，受控实验证据在 tests/harness/results/diag-c5/spacing/）；单行框宽按候选集最坏实测 ×1.08（标点密集 ×1.15） |
| 7 | "候选字体集全局最坏值"误伤 | Noto Mono 的 em=1.17 被摊到正文轨 | 按声明族名分轨取最坏，不做全局最坏 |
| 8 | 行聚类把同行混排小字撕成伪行（'1128km'→两行） | 按 top 聚类对字号混排敏感 | 纵向区间相交聚类 + 行内按 left 排序 |
| 9 | 远屏页快照拿到塌缩行（全文一行） | content-visibility:auto 远屏不排版 | 快照前强制 contentVisibility='visible' |

## 三、扫描、修复环与门禁

| # | 坑 | 根因 | 正解 |
|---|---|---|---|
| 10 | 93% 文本框的宽度余量被相交扫描收回 | 扫描以"框"为对象，余量伸入空白被误判冲突 | **墨水盒判定**：只有墨水相碰才算冲突，余量区豁免 |
| 11 | 文本骑缝压卡片边缘不报警 | 净距规则只查"完全包含" | 部分相交即违规（骑缝检测）；全页背景底走包含分支；环形/圆形豁免 |
| 12 | 修复环在两卡缝间振荡 11 轮不收敛 | 挪位策略无记忆 | 停摆检测（两轮不降→页级降级兜底）+ 环末重建 + 终认证 |
| 13 | 修复环把文本块烙成图（p18 文字截图事件） | 烙图兜底对文本越界 | **文本永不烙图**【硬规则】：文本阶梯=挪位→缩字→页级降级；烙图仅限装饰/复杂视觉层 |
| 14 | LO 回验对"内嵌字体失效"类故障全盲 | fontconfig 把内嵌族名解析回本机字体，剥不剥内嵌渲染逐点相同 | 主门禁=数学认证（certify-pptx）；LO 降级为参考通道 |
| 15 | 像素 diff 对文字重叠钝感（重叠不移除文本层） | 像素口径与故障类型不匹配 | 按故障类型选检测器：重叠→几何相交，错字→文本多重集，灾难→像素 diff |
| 16 | 容量闸过但导出认证不过（16 页假降级） | 两闸度量口径漂移（换行基准/常数/折扣各不相同） | 两闸同函数同常数（原则 3）；verify with 143/143 逐元素一致性实验 |

## 六、治理纪律（本轮验证有效的）

- **代表页闸门**（烙入先生一页再批量）在生图场景有效；导出场景的等价物 = 认证门禁全过才落盘；
- **"宁可降级不可错映射"**：图表双源校验不过就烙图，错数据进原生 chart 是幻觉不是降级；
- **高密度真实内容是最好的人选矿**：cmb-retail 54 页基准逼出了混排间距、两闸漂移、修复环振荡三组深层问题，玩具 fixture 一个都测不出来；
- **借鉴三源的分工**：ppt-master 给 DrawingML 工程知识与字体表（代码级）；slide-paipai 给"余量哲学"与逐行 a:p 的反例（坑位记录级）；tencent-pptx 给"lint 不过不落盘"的纪律（流程级）。
